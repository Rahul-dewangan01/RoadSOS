# Road SoS Backend

This is the backend/database service for Road SoS.

## Run locally

```bash
cd backend
npm install
npm run dev
```

## Google Maps setup for deployment

Create `backend/.env`:

```env
PORT=8080
DATABASE_PATH=./roadsos.sqlite
APP_ORIGIN=*
GOOGLE_MAPS_API_KEY=your_real_google_maps_api_key
```

Enable **Places API (New)** in Google Cloud for that key, then restart:

```bash
npm run dev
```

The Android app points to `http://10.0.2.2:8080/api` by default, which works from the Android emulator. For a physical phone, set `BackendClient.BASE_URL` to your computer's LAN IP, for example `http://192.168.1.20:8080/api`.

## Notes

- The database is SQLite at `backend/roadsos.sqlite`.
- Phone numbers must use E.164 format, for example `+919876543210`.
- Email addresses must be Gmail addresses.
- OTP is generated by the backend. In development it is returned as `devOtp` so the app can be tested without SMS provider credentials.
- To send real SMS OTPs, connect Twilio Verify inside `server.js` where marked.
- To verify real Google OAuth ID tokens, add a Google client ID and verify the ID token in `/api/auth/google`.
- For deployment-grade Nearby Emergency Services, set `GOOGLE_MAPS_API_KEY` with Places API (New) enabled. Without it, the backend uses OpenStreetMap Overpass as a real-data fallback.

## Offline emergency directory

For offline reliability, maintain a verified directory file at:

```text
backend/emergency-services.json
```

Use `backend/emergency-services.example.json` as the schema. Each record should include:

- `name`
- `type`: `hospital`, `ambulance`, `police`, `fire`, `trauma_center`, or `vehicle_rescue`
- `latitude`
- `longitude`
- `phone`
- `address`
- `operatingArea`
- `lastUpdated`

On backend startup, this file is imported into SQLite. If Google/Overpass fails, `/api/nearby-emergency` automatically falls back to this stored directory.
